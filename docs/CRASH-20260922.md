# Windows host crash during the first encounter

The affected release repeatedly crashed with Windows exception `0xc0000005`
at `RemZ.exe + 0x1bedac7`. The crash dump identifies a null Skeleton3D receiver
in `get_bone_global_pose`. Host termination disconnects every client.

The binary resource exporter loses the nested `Array[Plane]` element type in
`zombie_hit_volumes.tres`. Calling `HitVolume.configure` with the resulting
untyped array fails before assigning the skeleton. The release then retains
uninitialized hit volumes and crashes when a shot queries their bone pose.
The debug export reports the rejected fourth argument at `zombie.gd:340` in
the original source. Walking without firing does not exercise this path.

`Zombie._load_volume_library` now restores the element type once for each
shared hull during loading. Actor spawning and shooting reuse those arrays.
The network build identifier changed so the affected release cannot join
the corrected build.

Validation on 22 September 2026:

- The original release test reproduced a native access violation.
- The corrected editor and release tests passed all 77 hit-volume checks,
  including all model variants, animated hit precision, headshots, piercing,
  exclusions and fallback to native collision for changed hulls.
- Three release processes walked the intro route for 100 seconds with the
  first wave active. Host/client/client fired 180/168/168 shots; all exited 0.
- The distributable Windows executable rendered all nine automated views
  using Vulkan Forward+ and exited 0 without script or shader errors.

The local three-player test is headless and uses bounded loading warm-up.
It does not establish Internet/Hamachi reliability or long-session performance.

To reproduce the release checks, run `python tools/export_packed_tests.py`.
This creates `builds/crash-test`, leaving `builds/windows` unchanged. The
normal project scene and export exclusions are restored after export.
Run the test executable with `--headless -- --suite=horde_hit_precision`.
For the route test, start three copies with `--headless -- --suite=coop_intro_route
--route-role=host` (then `one` and `two`), adding `--route-walk --route-shoot
--smoke-test --no-foliage` to each. Tests are excluded from the normal release.
